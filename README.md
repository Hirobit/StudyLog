# StudyLog

学習記録・日記・成長記録など、**時間軸の変化を追いたいあらゆる事象**を体系的に記録・管理するWebアプリです。

PCのフォルダ構造のように階層を作り、時間の流れに沿って記録を積み上げていくことができます。

🔗 **公開URL：** https://studylog-03pu.onrender.com

Googleアカウントでログインして利用します。データはユーザーごとに分離されており、他のユーザーから閲覧・編集されることはありません。ログ単位で公開・非公開を選択でき、公開に設定したログはログイン不要で閲覧できます。ログイン画面の「ゲストモードで公開ログを見る」から、ログインせずに公開ログ一覧へアクセスできます。

---

## 📌 コンセプト

「時間軸の変化を追える事象には、体系的な階層構造が有用である」

学習記録はもちろん、日記・子供の成長記録・読書記録など、継続的に記録したいことであれば何にでも活用できます。

## 🖥️ 画面構成

```
ログイン画面
  └── カテゴリ選択（画面1）
        └── サブカテゴリ＋ログ一覧（画面2）
              └── 詳細ログ（画面3）

公開ログ一覧（ログイン不要）
  └── 公開ログ詳細（ログイン不要）
```

**画面1 - カテゴリ選択**
トップページ。記録の大分類をサイドバーで管理します。

**画面2 - サブカテゴリ＋ログ一覧**
カテゴリの中分類と、日付・タイトルのログ一覧を表示します。

**画面3 - 詳細ログ**
ログの詳細（タイトル・メモ・不明点）を表示します。メモと不明点はその場で直接編集・保存できます。公開・非公開もこの画面から切り替えられます。

**公開ログ一覧・詳細**
公開設定にしたログのみ、ログイン不要で誰でも閲覧できる画面です。

PC・スマートフォン両方のレイアウトに対応しています。スマートフォンではカテゴリ→サブカテゴリ→ログの各階層をタップで切り替えながら閲覧する設計です。

## 🚀 主な機能

- Googleアカウントによるログイン認証、ユーザーごとのデータ分離
- カテゴリ・サブカテゴリ・詳細ログの3階層管理
- 各階層の追加・編集・削除（`···`ドロップダウンメニューから操作）
- カテゴリ・サブカテゴリ削除時のカスケード削除（配下データも連動して削除、削除前に警告表示）
- 詳細ログへのメモ・不明点の記録（改行対応）
- ログ単位での公開・非公開切り替え、公開ログ一覧・詳細のログイン不要閲覧
- ログイン画面からのゲストモード導線（ログイン不要で公開ログ一覧へ直接アクセス）
- カテゴリ一覧のスライドサイドバー
- PC／スマートフォン対応のレスポンシブデザイン

## 🔧 ローカル環境での起動方法

### 前提条件
- Python 3.11以上
- PostgreSQL（またはSupabaseなどのホスティングDB）
- Google Cloud ConsoleのOAuthクライアントID

### セットアップ

```bash
# 依存ライブラリのインストール
pip install -r backend/requirements.txt

# 環境変数の設定
# backend/.env を作成して以下を記述
DATABASE_URL=postgresql://localhost/studylog
GOOGLE_CLIENT_ID=（Google CloudのOAuthクライアントID）
JWT_SECRET_KEY=（ランダムな文字列）

# サーバー起動
cd backend
uvicorn main:app --reload
```

フロントエンドは`frontend/login.html`をローカルサーバー経由で開いてください（`file://`での直接オープンはGoogleログインが動作しません）。

## 📋 API一覧

| 対象 | メソッド | エンドポイント | 認証 |
|---|---|---|---|
| 認証 | POST | /auth/google（GoogleトークンをJWTに交換） | 不要 |
| 認証 | GET | /auth/me（ログイン中ユーザー情報取得） | 必要 |
| カテゴリ | GET | /categories | 必要 |
| カテゴリ | POST | /categories | 必要 |
| カテゴリ | PUT | /categories/{id} | 必要 |
| カテゴリ | DELETE | /categories/{id}（カスケード削除） | 必要 |
| サブカテゴリ | GET | /subcategories/{category_id} | 必要 |
| サブカテゴリ | POST | /subcategories | 必要 |
| サブカテゴリ | PUT | /subcategories/{id} | 必要 |
| サブカテゴリ | DELETE | /subcategories/{id}（カスケード削除） | 必要 |
| ログ | GET | /logs/{subcategory_id} | 必要 |
| ログ | GET | /logs/detail/{id} | 必要 |
| ログ | POST | /logs | 必要 |
| ログ | PUT | /logs/{id} | 必要 |
| ログ | DELETE | /logs/{id} | 必要 |
| 公開ログ | GET | /public/logs（公開ログ一覧） | 不要 |
| 公開ログ | GET | /public/logs/{id}（公開ログ詳細） | 不要 |

「必要」の項目はすべて、リクエストヘッダーに `Authorization: Bearer <JWT>` が必要です。

## 🔒 セキュリティ対策

- 全CRUD APIにおいて、リクエストしたユーザー自身のデータのみ操作可能（IDOR対策）
- CORSは本番URLとローカル開発環境のみ許可
- 個人情報の最小化（Googleアカウントのemailは保存せず、google_idのみで認証）
- ユーザー入力（カテゴリ名・ログタイトル等）はテキストとして安全に描画し、HTMLインジェクションを防止
- 保存ボタンの連打による重複データ作成を防止
